1. Lead Qualification Agent Done, ready to show

Problem: A business gets a long lead list and does not know who to contact first.

Solution: The agent scores each lead 0-100 for email, phone, website, industry fit, and location, grades it A / B / C, and drafts a short personalised first email for A and B leads. No price in the first email. No contact is guessed.

Tech: Python, FastAPI, CSV

2. Document RAG Agent Done, ready to show

Problem: A business has documents but no quick way to find the right answer in them.

Solution: Ask a question over your own documents and get an answer quoted from those documents, with the source file, section and score. If nothing matches, it says "No relevant section found" instead of guessing.

Result: Tested on 3 fictional sample documents, including the refund policy (14 days, unused part only after full delivery) and the starter package ($200/month in the fictional example).

Real run: The same code was also run on Faryal's own real documents: her portfolio services text and the Project 1 and Project 5 READMEs. It quoted her working method correctly (Discovery - Small working version - Paid pilot - Full project), found the Meta 20% budget-change limit and the lead scoring rules in the top 2 results, and correctly said "No relevant section found" for an unrelated weather question.

Tech: Python, FastAPI, keyword / TF-IDF retrieval

Honest limit: this agent does not use an LLM; answers are quotes from the documents, not generated text.

3. Multi-Agent Research and Outreach Workflow Done, ready to show

Problem: Research, drafting and checking are usually done by hand, one after another.

Solution: Three agents in sequence: Researcher finds only notes that exist in the sample data, Writer drafts from those facts only, and Reviewer fails a draft that contains a price not in the facts, a guessed email, a guaranteed-result claim, a missing fact, or more than 200 words.

Result: Tested on "lead generation" for "small cafes" with reviewer PASS.

Real run: The same workflow was also run on real facts about Faryal's own work, for "lead generation" for "small businesses". Researcher found 2 matching facts, Writer drafted only from those facts with sources, and Reviewer verdict was PASS, with no price, email or guaranteed claim in the draft.

Tech: Python, FastAPI

Honest limit: these are rule-based functions, not LLM agents.

7. Multi-Agent Business Assistant Done, ready to show

Problem: A small business loses time on lead follow-up, searching documents for answers, and drafting the same emails again and again, with no one checking the draft before it goes out.

Solution: Four agents work together in one system: a Researcher finds facts with sources and scores leads, a Writer drafts from those facts only, a Reviewer checks the draft and gives a PASS or FAIL with reasons, and a Tool Agent runs four tools — score_lead, search_docs, draft_email and add_numbers. A FastAPI app runs the workflow, and nothing is sent without human approval.

Result: On the real 19-lead USA real estate sample, LEAGUE Real Estate scored 100 / A - Contact first. For "lead generation" for "small cafes", the full run found 3 facts with sources and the Reviewer gave a PASS, with approval status PENDING_APPROVAL. An unrelated question correctly returned "No relevant section found".

Tech: Python, FastAPI, RAG, MCP tools, Docker, CI/CD

Real run: The lead score and the RAG answers were run on real sample data as above. This is not a production client result, and no client has used it in production yet.

Honest limit: this agent is rule-based with quoted answers, plus an optional LLM via the client's own API key in .env. It does not send any email on its own, and no action is taken without human approval.
